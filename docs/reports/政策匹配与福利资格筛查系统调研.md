## 1. PolicyEngine（policyengine.org）

### 技术路线：规则即代码（rules-as-code），非 LLM

- 定位是**税收—福利微观模拟模型（microsimulation）**，不是对话式助手。核心是确定性的 Python 计算，无任何 LLM 参与。
- 四层架构（JOSS 论文明确）：
  1. `policyengine-core`：可复用的模拟抽象、版本化参数、数据集接口（开发团队**从 OpenFisca fork 而来**，论文原文："originally forked the codebase from OpenFisca and built it on the policyengine-core framework"）。
  2. `policyengine-us` / `policyengine-uk`：国别法定规则与变量、实体结构。
  3. `policyengine`：面向分析者的编排层，提供 `calculate_household()`、`Simulation`、`Aggregate` 等。
  4. 配套微观数据仓（美国 Enhanced CPS、英国 FRS）。
- 规则表示：**变量用 Python 函数定义（按年度、按实体）**，**法定参数用 YAML 存**（如 `gov.irs.credits.ctc.amount.base[0].amount`）。改政策=改 dict 形式的参数路径，不写代码。
- 实体层级（决定"一次计算"的输入形态）：`person / marital_unit / tax_unit / spm_unit / family / household`；美国模型必须提供六个实体组。
- 取值原则：法条与表单/机构实践冲突时**以法条为准**，冲突记录在 `known-source-conflicts.yaml`（与 Axiom Foundation 共享的 source-conflict register）。
- 确定性、可版本钉扎：`policyengine` 4.x 引入"认证运行时 bundle"，绑定 模型版本 + 数据工件，导入时做强校验。

### 覆盖规模

| 指标 | 数值 | 口径 |
|---|---|---|
| 变量（variable）定义文件 | **7,097** | `policyengine_us/variables/**/*.py`，GitHub API 递归树统计（main 分支，2026-11-03） |
| 参数（parameter）文件 | **7,560** | `policyengine_us/parameters/**/*.yaml`，同上 |
| 州级目录 | **51**（50 州 + DC，无遗漏） | 参数树中州代码目录统计 |
| 政策项目（模块） | 变量树顶层共 **114 个目录**，其中 51 个为州、其余为项目/领域模块 | 可从变量树目录直接核实的项目模块包括：`snap, tanf, medicaid, chip, medicare, basic_health_program(ACA), credits(eitc/ctc/cdcc), childcare, ccdf, housing, school_meals, fdpir, csfp, lifeline, pell_grant, student_loans, head_start, utilities(LIHEAP), social_security, retirement, basic_income, education, health, vehicle, high_efficiency_electric_home_rebate, residential_efficiency_electrification_rebate` 等（目录名逐字取自仓库，未在此列举的模块仅表示未展开核实） |
| 国别 | 美国、英国 | 官方站与 JOSS 论文 |

**"覆盖多少条政策"没有官方条数口径**——PolicyEngine 用"变量/参数/项目"计数，而不是"政策条数"，这一点与国内"归集政策 N 条"的口径不可直接比较。

### 响应时间

- **官方未公布单次资格计算的耗时指标**（文档、JOSS 论文、API 文档均无 SLA/延迟数字）。论文只给出量级描述：population-scale 运行"can require several gigabytes of memory"，美国 Enhanced CPS 是最重的负载。
- **本次实测（自测，非官方）**：对公开、免鉴权的 `POST https://api.policyengine.org/us/calculate`，单户（1 成人、30 岁、$50,000 工资、CA）请求 `eitc` 与 `snap` 输出，端到端 HTTP 耗时 3 次为 **2.96 s / 1.26 s / 1.47 s**（首次含冷启动）。即稳态约 **1.3–1.5 s**，冷启动约 3 s。测量环境为本次调研主机，经公网访问，含网络 RTT，不代表其服务端纯计算时间。
- 另有需 OAuth 的托管端点 `household.api.policyengine.org/us/calculate` 与可自托管的 Docker 镜像（GHCR），官方未给性能基准。

### 准确率 / 召回率

- **未以单一"准确率"公开**。公开的验证方式是**校准 + 三方交叉比对**：
  - 与 Federal Reserve Bank of Atlanta 的谅解备忘录下，对美国模型做 **PolicyEngine vs TAXSIM vs Atlanta Fed Policy Rules Database 三方比对**；
  - 微观数据经校准（calibration），并有 validation/calibration diagnostics 页面；
  - 曾事前提早注册并事后评分 2025 年 SPM 贫困率预测（官方自评误差：总体 +0.2pt vs 普查局 +0.1pt，儿童 +0.9pt vs −0.1pt），这属于**聚合预测**精度，不是逐户资格判定精度。
- 因此：**逐户资格判定的准确率/召回率：未公开**。

## 5. 学术侧：规则/知识图谱 方法 vs LLM/RAG 方法

### 5.1 关键发现：直接可比的"端到端资格判定准确率"对比几乎不存在

检索到的公开对比数据集中在**检索环节（recall）**而非**最终资格判定（accuracy）**。这是本领域的一个真实空白，值得记录。

### 5.2 有硬数字的一篇：RAG 的"语域错配"导致召回崩塌

**《The Vocabulary Gap Is an Equity Gap: Register Mismatch in Retrieval Systems for Public Benefits》**（arXiv 2609.01645，2026-08）

- 构建了受控基准：**51 条公开记录的联邦福利资格规则** × **25 个信息需求**，每个需求分别用"机构语域（agency register）"和"用户口语语域（plain register）"表述，**金标准段落固定不变**。
- 检索器：BM25、TF-IDF、term-graph retriever。

| 指标 | 正式/机构语域 | 口语/用户语域 | 差距 |
|---|---|---|---|
| Recall@5（BM25/TF-IDF/term-graph） | **96–100%** | **36–44%** | 崩塌 |
| BM25 Recall@1 | **84%** | **16%** | −68pt |
| BM25 Recall@5 | **100%** | **44%** | −56pt |
| 查询词与金标准段落的内容词重合度 | 0.63 | 0.11 | 5.9× |

- 缓解：一个刻意简单、可审计的"口语→正式"词典桥，把口语查询的 BM25 Recall@5 从 **44% 提升到 80%**。
- 作者定位：贡献不是新检索器，而是**评测协议 + 基准 + 机制诊断 + 透明缓解**。
- 意义：说明**纯 RAG/向量检索方案在"老百姓口语提问 → 政策条文"这一步就会丢一半以上召回**，与规则引擎的确定性形成鲜明对比。

### 5.3 规则/本体 + 求解器路线：CalFresh 的可解释资格判定

**《A Neuro-Symbolic Framework for Accountability in Public-Sector AI》**（arXiv 2512.12109，v4，2025-12）

- 面向加州 CalFresh（SNAP）的自动资格判定，做的是**"判定解释是否合乎法条"**的可解释性框架：
  - 从州 **MPP（Manual of Policies and Procedures）** 抽取资格要件，构建**结构化本体（ontology）**；
  - 规则抽取流水线把法条逻辑表达为**可验证的形式化表示**；
  - **求解器（solver）推理层**校验系统给出的解释是否与法条一致。
- 能检测"法律上不一致的解释"、定位被违反的资格规则。
- **未给出准确率/召回率/延迟数字**（学位论文性质，以案例评估为主）。

### 5.4 方法学对照（定性，基于上述两篇 + 领域通识，未编造数字）

| 维度 | 规则/知识图谱/求解器 | LLM/RAG |
|---|---|---|
| 判定确定性 | 高（同输入同输出，可版本钉扎） | 低（概率生成，需额外约束） |
| 可解释/可审计 | 强（规则编号可追溯，如 Access NYC 的 S2R###） | 弱到中（需 neuro-symbolic 层补） |
| 口语鲁棒性 | 差（需先把口语映射到结构化字段） | 强（但检索召回受语域影响，见 5.2） |
| 覆盖扩展成本 | 高（每条政策要人写规则/参数） | 低（文档入库即可） |
| 公开的准确率对比 | **无统一基准** | **无统一基准** |

### 5.5 检索方法说明

arXiv API 以 `all:"eligibility" AND all:"LLM"` 检索，返回的**绝大多数是临床试验入组（clinical trial eligibility）**方向（如 RECITE、AMEND++、Eligibility-Aware Evidence Synthesis），与福利政策匹配不是同一问题域，故未纳入。OpenAlex 的 title/abstract 检索对 "mRelief SNAP screening" 返回 0 条，对 "benefit eligibility screening rules engine" 仅 9 条且多为不相关。**中文核心期刊（知网/万方）不可达**，因此国内"政策匹配/知识图谱"论文的对比数据未能覆盖。
