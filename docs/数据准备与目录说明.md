# 数据准备与目录说明

本文说明**代码仓库之外**需要恢复/准备哪些数据、放在哪里、谁读取、缺失会怎样，以及哪些数据永远不能进 Git。
配套阅读：[部署与启动指南](部署与启动指南.md)（恢复与启动步骤）、[README](../README.md)（项目总览）。

> 三条铁律：
> 1. **真实数据只在本机**：个人信息、政策原文、真实密钥、模型权重都不入库。
> 2. **路径与文件名必须与本文一致**：证据链按文件名 + SHA256 定位原始文件，改名/挪目录等价于删文件。
> 3. **占位 README 只是分类说明**：`data/个人信息数据/`、`data/政策数据/` 等目录里没有真实文件，真实文件仍放 `data/` 根、`data/policy_db/` 等固定路径。

## 4. 恢复顺序与校验

### 4.1 恢复顺序

```bash
# ① 挂载私密包
lsblk
sudo mkdir -p /media/usb && sudo mount /dev/sdX1 /media/usb

# ② 先校验交付完整性（失败不要继续）
cd /media/usb/smart-help-private-data
sha256sum -c MANIFEST-SHA256.txt

# ③ 按相对路径整体恢复（-a 保留时间戳/权限）
cd <项目根>
rsync -a /media/usb/smart-help-private-data/restore/ ./

# ④ 收紧权限
chmod 600 deploy/web.env deploy/web.gray.env config/model_settings.yaml
chmod -R go-rwx data src/data models runtime run 2>/dev/null || true

# ⑤ 单独确认政策证据包引用的原始文件
python3 - <<'PY'
import hashlib, json, os
root = os.path.abspath('data')
bundle = json.load(open('src/data/policy_evidence/bundle.json', encoding='utf-8'))
for name, rec in bundle.get('original_files', {}).items():
    path = os.path.join(root, name)
    actual = hashlib.sha256(open(path, 'rb').read()).hexdigest() if os.path.isfile(path) else None
    print(('OK  ' if actual == rec.get('sha256') else 'FAIL'), name)
PY

# ⑥ 卸载 U 盘
sudo umount /media/usb
```

> 顺序原则：**先恢复数据再启动服务**。若先启动，首次问答会缓存“证据缺失”的降级结果；补数据后重启即可恢复（缓存可删）。

## 5. 为什么 `data/*.xlsx` 不能改名、不能挪目录

机制在 `src/policy_core/local_evidence.py`：

1. 证据包 `bundle.json` 的 `original_files` 记录 `{文件名: {sha256, ...}}`；
2. `POLICY_SOURCE_ROOT`（默认 `<项目根>/data`）是这些文件的**唯一根目录**，代码通过 `root / name` 拼接路径；
3. 每个文件做**文件字节 SHA256** 校验，并额外要求解析后的父目录就是 `POLICY_SOURCE_ROOT`；
4. 不通过时写入 `invalid_files`，错误码为 `local_evidence_bundle_missing` / `local_evidence_bundle_invalid` / `original_file_changed_or_missing:<name>` / `original_sheet_mismatch`（工作簿结构变化时）；
5. 结果是**证据链降级**：问答仍能跑、政策仍能匹配，但卡片缺少“原文依据/页码”，前端会标注证据缺口。

所以：

- 改名 = 找不到文件 = 缺依据；
- 挪到 `data/政策数据/` = 路径不再是 `POLICY_SOURCE_ROOT` 直接子文件 = 缺依据；
- 用 WPS/Excel 另存、重新排版、改动 sheet 名 = sha256 变化 = 缺依据；
- 当前 `original_files` 只登记了 2 个文件（`县级帮扶工具箱_更新至9月22日.xlsx`、`2026年防止返贫致贫对象帮扶政策“明白纸”(0715).wps`），其余 9 个暂不参与校验；**但不要把“暂不校验”当成可以改名的许可**——后续重建证据包会把它们纳入。

若确实需要更新原始政策文件，走 §7 的更新流程并**重新生成证据包**，不要手工替换。

## 7. 数据更新流程（运营）

```bash
cd <项目根>
set -a; . deploy/web.env; set +a

# ① 全国政策投递：把 csv/xlsx/json 放进 data/incoming/
python deploy/national_intake.py                  # 默认 dry-run，先看报告
python deploy/national_intake.py --apply          # 需 POLICY_IMPORT=1
python deploy/national_intake.py --json           # 机器可读报告

# ② 结构化政策导入（单事务，可回滚）
python deploy/import_policies.py --file <政策清单.csv>          # 默认 dry-run
POLICY_IMPORT=1 python deploy/import_policies.py --file <政策清单.csv> --commit
python deploy/import_policies.py --batch-id <id> --report
python deploy/import_policies.py --batch-id <id> --rollback
```

- 入库字段与校验见 `data/policy_db/命名规则.md`、`2026年帮扶政策汇总_入库格式.xlsx`；
- `--apply` / `--commit` 需要 `POLICY_IMPORT=1`，否则退出码 2 直接拒绝；
- 政策生命周期操作（暂停/归档/恢复/删除/发布/回滚）由后台“政策管理”页面完成，写 `outbox` 异步生效。

**证据包重建**（政策原文变化后必须重做，否则证据链会持续降级）：目前仓库未包含公开的重建脚本入口，需向交接人索取 `bundle.json` 生成流程（**待确认**）。重建后必须更新 `original_files` 中受影响文件的 sha256，并重新跑一次 §4.1 ⑤ 的校验。

**向量重建**（更换嵌入模型/维度时）：`src/reindex_vectors_2560.py`、`src/vector_reindex.py`、`src/restore_vector_backup.py`；重建前先确认 `EMBED_PLATFORM`、`POLICY_VECTOR_TABLE`、`embed_dim=2560` 三者一致。

## 8. 容量、备份与清理

| 项 | 参考大小 | 增长/备份建议 |
|---|---|---|
| 政策与业务数据（`data/`） | 约 29 MB（其中 `policy_db/` 约 21 MB） | 变化即备份，纳入版本化私密包 |
| `data/policy_db/exports/` | 每份几十 KB–数 MB | 按需清理；**备份时单独加密** |
| 证据包（`src/data/`） | 约 34 MB | 只在重建时变化 |
| 模型（项目外） | 约 28 GB | 单独蓝本/介质，不进任何包 |

| 日志 `runtime/logs/`、`src/logs/` | 持续增长，`autostart.log` 自动轮转 | 定期归档；对外提供前脱敏 |
| 数据库（Kingbase） | 政策库 + 账号库 | 用 `sys_dump` 逻辑备份；恢复用 `sys_restore`（见部署指南 §5.3） |

备份策略建议：政策库与账号库每日 `sys_dump` 到独立磁盘；`data/` 与 `src/data/` 每周加密打包；私密包交付前后各校验一次 `MANIFEST-SHA256.txt`。

## 9. 首启后建议轮换的密钥清单

| 密钥 | 位置 | 轮换影响 | 生成方式 |
|---|---|---|---|
| 政策库应用账号口令 | Kingbase + `ADMIN_DB_URL` | 重启 Web 生效 | 随机 ≥ 20 位 |
| 账号库应用账号口令 | Kingbase + `SMART_HELP_AUTH_DATABASE_URL` | 重启 Web 生效 | 随机 ≥ 20 位 |
| `SMART_HELP_AUTH_JWT_SECRET` | `deploy/web.env` | **所有登录态立即失效** | `openssl rand -hex 32`（长度必须 ≥ 32） |
| `ADMIN_SECRET` | `deploy/web.env` | 后台 session 失效 | `openssl rand -hex 32` |
| 云端模型 api_key | `config/model_settings.yaml` | 该云端平台不可用，本地链路不受影响 | 平台控制台重新签发 |
| Kingbase `system` 口令 | 数据库 | 仅运维使用 | 按数据库规范 |
| 管理员初始口令 | 账号库 `admin_user` | 用 `python manage_auth.py admin` 重置并强制下次登录修改 | — |

轮换后执行 `bash deploy/stop.sh && bash deploy/start.sh`，再跑 `bash deploy/status.sh` 验收。
