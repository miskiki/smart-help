# M3 数据层第二步：确定性条款切分（契约与只读统计）

状态：新增模块，尚未接入现有链路（2026-11-08；本次只新增 3 个文件，不改现有模块、不写库）
代码：src/policy_core/clause_split.py
测试：tests/test_clause_split.py（19 例）

## 1. 一句话结论

新增纯函数 clause_split.split，把 policy_detail 的 conditions/target/benefit 按显式句末标点与换行切成带绝对偏移的片段：不调模型、不做语义分类、同一输入永远同一输出。400 行只读抽样中，conditions 平均 1.66 条/行、中位 1 条，target/benefit 平均 1.0 条/行；全部 1467 个自然条款平均 25.7 字、中位 13 字、最长 306 字。分隔符里句号只占 55.2%，分号 28.0%、换行 16.8%——只按句号切会漏掉约 45% 的边界，这是必须同时覆盖分号与换行的数据依据。

## 2. 契约

### 2.1 输入

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| text | str / None | 必填 | 原文。None、空串、纯空白一律返回 []；其他非 str 抛 TypeError |
| kind | 任意 | None | 仅原样写进每个片段的 kind 字段，不参与切分，不做校验/归一 |
| max_len | int / None | None | 正整数时对仍超长的片段按字符数硬切；None 表示只按标点/换行切 |

### 2.2 输出

list[dict]，按原文顺序排列，每个 dict 的键固定为 idx/start/end/text/kind：

| 键 | 含义 |
| --- | --- |
| idx | 输出序号，从 0 递增；被丢弃的碎片不占号 |
| start | 片段首字符在原始 text 中的下标（含） |
| end | 片段尾后下标（不含）；text[start:end] == text 字段 |
| text | 恰好等于 text[start:end]，两端无空白，句末标点不在片段内 |
| kind | 调用方传入的 kind 原值（默认 None） |

关键不变量：

1. 绝对偏移：start/end 是原文本坐标，不是片段内坐标；片段按 start 升序、互不重叠。
2. 可还原：片段之间允许空洞（被丢弃的空白、句末标点、过短碎片都留在原文坐标里）。按下面的方式拼接，必须逐字等于输入：

        text[:p0.start] + p0.text + text[p0.end:p1.start] + p1.text + ... + text[pn.end:]

   例如「第一句话。」返回一个片段 [0,4)，第 4 位的「。」不在片段里；按偏移补回空洞即可还原整句。这是「含被丢弃的空白/标点」的可执行定义。
3. 不猜语义：不判断条款类型（对象/条件/标准/材料/流程），不合并、不改写、不做同义归一；kind 只透传。
4. 确定性：纯字符扫描，不读环境、不连库、不调用模型；相同输入在任何机器上输出相同。
5. 幂等：split(text) 反复调用结果相同；把任一片段的 text 再 split（不传 max_len），得到它自身的单片段。

### 2.3 切分与丢弃规则

- 分隔符固定为「。；;！？!?」和换行符 \n、\r（覆盖 CRLF）；分隔符本身不进入片段。
- 逗号「，,」、顿号「、」、冒号「：:」、英文句点「.」都不切：它们是句内并列/小数/编号的一部分，切开会产生大量无主语碎片。
- 连续分隔符之间产生空片段，按纯空白丢弃；不会输出空 text。
- 片段两端只去空白（isspace，含全角空格/Tab），不去引号、括号等内容字符。
- 纯空白与长度 < 4 的碎片丢弃；长度按 Python 字符数计（一个汉字/ASCII 字符/emoji 码点均为 1），恰好 4 字保留。
- max_len 是硬上限：对已通过最短长度检查的句子，按固定窗口 [start, start+max_len) 切，不寻找逗号/词边界；每个输出片段长度 <= max_len。末尾不足 4 字的残片按同一规则丢弃（原文仍在空洞里，偏移可还原）。
- max_len 为 bool、非 int、<= 0 时分别抛 TypeError/ValueError。

### 2.4 为什么必须确定性切分

1. 证据可定位：规则原子与 claim 的 quote 必须能指回原文的逐字片段；绝对偏移是「这句话来自 policy_detail 哪一行哪一段」的最小指针，后续可升级为 clause_id。
2. 可复现/可回滚：切分结果只由输入文本决定，重跑、换机器、换批次都不会漂移；出了错能按同一输入复现。
3. 不把语义错误沉淀成数据：条款类型、条件原子应由后续抽取层基于原文判断；切分层若「顺手」分类，错误会写进库，后续检索/规则都继承。
4. 成本与延迟：政策明细有 9403 行，纯字符扫描是 O(n)、微秒级；不占模型预算，也不会因模型服务不可用而阻塞数据流水线。
5. 可单测：不连库、不调模型，测试可在任何环境跑；本文件的 19 个用例全部是标准库 unittest。

## 5. 风险与未做事项

1. 最短长度会丢短值：400 行样本里 13 行 conditions、98 行 benefit 切出 0 条（如「100」「新生儿」「新建」）。这是契约规定的丢弃，但接入方不能拿「条款行」当字段唯一真值；target/benefit 的短数值应继续读原字段，条款表只承担可引用的长文本。
2. 硬切不保证词边界：max_len 固定窗口可能截断词/数字；本样本 8878 的 120 字切点恰好落在「年收入/不低于」之间，未截断词，但规则本身不提供保证。若下游需要按词切，应在切分后另做，不要改变本模块的偏移契约。
3. 分号片段可能没有主语：如「（二）无生活来源」只有 7 字；语义抽取层必须结合同一 detail 的前后片段理解，不能把它当独立资格条款。
4. 只覆盖 \n/\r：U+2028、U+2029、\v、\f 等不切；当前库样本未发现，若上游出现需显式扩展 SEPARATORS 并补测试。
5. 纯标点但 >=4 字的内容会保留：契约只丢弃纯空白与 <4 字，不做「有没有语义」的判断；极端脏数据需在质量门另做规则。
6. 偏移是 Python 字符下标，不是字节偏移：Postgres/Kingbase 的 substring 也按字符计，可直接用；若下游按 UTF-8 字节切片会错位，必须统一按字符坐标。
7. 尚未接入链路：本次只新增模块/测试/文档，没有改 policy_detail 读取、规则编译、证据绑定，也没有建 policy_clause 表或写任何库；max_len=120、kind 取值（conditions/target/benefit）需由调用方约定。
8. kind 不做校验：传错标签不会被发现；这是「透传」的代价，接入时应由调用方枚举约束。
